# PlanForge: Idea-to-Implementation-Plan Generator

> Convert raw app ideas into a single, execution-ready `IMPLEMENTATION_PLAN.md` with a built-in **Anti-Slop Engine** that ensures AI coding agents (**Cursor**, **Claude Code**) build authentic, domain-tailored software with zero generic AI look.

---

## What is PlanForge?

When developers and founders "vibe code" with AI agents, generic prompts usually produce generic software: purple gradients, floating cards with 24px padding, bare loading spinners, em dash ridden copy, and hallucinated architectures.

**PlanForge** eliminates this problem through four integrated pillars:

1. **The 13-Section Master Template**: A structured methodology covering PRD, ASCII system architecture, concrete design tokens (hex), AI agent rules, vertical-slice task checklists, ADRs, and turnkey kickoff prompts.
2. **Anti-Slop Engine (36 Blacklist Rules)**: Injects strict design constraints preventing the generic "AI-generated" aesthetic (no purple glow, no sliding arrows, no placeholder stats, no bare spinners, no em dashes).
3. **Deterministic Quality Linter**: Evaluates generated blueprints client-side against 6 strict quality checks with automated remediation prompts ("Regenerate with Fixes").
4. **Live Streaming Engine**: Real-time token streaming via OpenRouter Chat Completions API with server-side validation and rate limiting.

## 13-Section Master Template Structure

Every plan generated by PlanForge contains these exact sections in order:

0. **Project Snapshot**: Name, one-line pitch, target user, core problem, and technical assumptions.
1. **PRD**: Problem statement, target personas, user stories, success metrics, MVP scope, and out-of-scope boundaries.
2. **Architecture**: Stack with justification, ASCII system flow diagram, directory structure, architectural rules.
3. **Design System (Anti-AI-Look)**:
   - *3.1 Subject Anchor*: Industry and audience vocabulary.
   - *3.2 Aesthetic Direction*: Named, opinionated visual identity anchored in the domain.
   - *3.3 Color Tokens*: 4 to 6 exact hex values (`#HEX`) with roles for Canvas, Surface, Accent, Border, and Text.
   - *3.4 Typography & Scale*: Deliberate font pairings and scale with line length limits.
   - *3.5 Layout Concept & ASCII Wireframes*: Alignment philosophy and screen layout wireframe.
   - *3.6 Spacing & Radius System*: Single spacing scale with varied radii for controls vs containers.
   - *3.7 Core Components & States*: Skeletons, empty states, error handling, success states.
   - *3.8 Motion & Transitions*: Purposeful user-driven animations.
   - *3.9 Real Content Rules*: Domain copy, realistic demo data, no placeholder text.
   - *3.10 Anti-Slop Blacklist*: Verbatim 36-rule blacklist block.
4. **Rules (AI Rulebook)**: Pre-coding workflow, Anti-Slop enforcement, security principles, testing standards, git commit format.
5. **Data Model**: Entities, schemas, TypeScript interfaces, relational mapping, access policies.
6. **Tasks**: Phased, small vertical slices (`TASK-001...`) including custom skeleton tasks and Anti-Slop audit tasks.
7. **Decisions (ADRs)**: `ADR-001...` recording architectural decisions, trade-offs, and rationale.
8. **Memory State**: Initial execution status, completed tasks, current task, known blockers.
9. **Test Plan**: Feature verification matrix + responsive breakpoints (375px, 768px, 1440px).
10. **Security & Privacy**: Server-side validation, secrets management, rate limiting, sanitization.
11. **Env Configuration**: `.env.example` template block for the target project.
12. **Kickoff Prompts**:
    - *(a) Context-loading prompt*: Prompts the agent to read and understand without coding yet.
    - *(b) Structured prompt for TASK-001*: Turnkey prompt with files, constraints, and report format.

## Anti-Slop Engine & Quality Linter

PlanForge includes a deterministic client-side linter (`src/lib/plan-lint.ts`) that audits every generated plan:

- `anti-slop-blacklist-present`: Verifies the 36-item Anti-Slop Blacklist is present verbatim.
- `no-em-dashes`: Verifies body text does not contain AI em dashes (`—`).
- `anti-slop-audit-task`: Verifies Phase 5 includes an Anti-Slop audit task.
- `skeleton-loader-task`: Verifies Phase 4 includes a custom content skeleton task.
- `non-generic-design-direction`: Verifies Section 3 has an authentic Subject Anchor and named Aesthetic Direction.
- `concrete-color-tokens`: Verifies at least 4 valid hex color tokens with defined roles.

If any check fails, the **Plan Quality Panel** displays the failed checks and enables 1-click regeneration with targeted fix instructions.

## Tech Stack

- **Framework:** Next.js (App Router) + TypeScript
- **Styling:** Tailwind CSS + Lucide Icons
- **AI Gateway:** OpenRouter Chat Completions (OpenAI-compatible streaming)
- **Markdown Preview:** `react-markdown` + `remark-gfm`
- **Validation:** `zod`
- **Rate Limiting:** In-memory sliding window limiter (Upstash-ready abstraction)
- **Testing:** `vitest`

## Quick Start (Local Setup)

### 1. Clone & Install Dependencies
```bash
git clone <repo-url> planforge
cd planforge
npm install
```

### 2. Configure Environment Variables
Create a `.env.local` file in the root directory:
```bash
cp .env.example .env.local
```

Fill in your OpenRouter API key and desired model in `.env.local`:
```env
OPENROUTER_API_KEY=your_openrouter_api_key_here
OPENROUTER_MODEL=openrouter/free
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
APP_URL=http://localhost:3000
APP_NAME=PlanForge
RATE_LIMIT_MAX=5
RATE_LIMIT_WINDOW_MINUTES=10
```

> **Security Note:** `.env.local` is git-ignored and must never be committed. The app strictly runs all LLM calls server-side to prevent API key exposure.

### 3. Run Development Server
```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

## Deploying to Vercel

1. Push your repository to GitHub / GitLab / Bitbucket.
2. Import the project in the [Vercel Dashboard](https://vercel.com/new).
3. Add the required environment variables under **Settings > Environment Variables**:
   - `OPENROUTER_API_KEY`
   - `OPENROUTER_MODEL` (e.g. `anthropic/claude-3.7-sonnet` or `google/gemini-2.5-pro`)
   - `OPENROUTER_BASE_URL` (`https://openrouter.ai/api/v1`)
   - `APP_URL` (e.g. `https://your-domain.vercel.app`)
   - `APP_NAME` (`PlanForge`)
4. Click **Deploy**.
